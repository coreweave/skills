What Weave is, in one breath

Weave is W&B's layer for tracing and evaluating LLM apps. For our purposes it's two ideas:

  • An op — any Python function you decorate with @weave.op(). Every call gets logged (inputs, output, timing) to your project. That's "tracing."
  • An Evaluation — a dataset of examples × a set of scorers, run together and logged as a comparable result. That's the eval harness (Parts 3-6).

Both write to a project you open in the browser at wandb.ai. Today we just create that project and confirm an op shows up in it.

Prerequisites

  • A W&B account (you set this up during onboarding).
  • Your API key from wandb.ai/authorize.
  • Python 3.9+ with a virtual environment you're comfortable installing into.
1

Install Weave (pip, inside a venv)

Not brew install weave. Homebrew's weave formula is an unrelated container-networking tool. W&B Weave is a Python package — install it with pip.
# Use a venv: on macOS, global pip is often blocked (PEP 668).
python3 -m venv ~/.venvs/weave-evals
source ~/.venvs/weave-evals/bin/activate

# weave = tracing/evals. wandb = login + entity resolution + judge endpoint.
# (Weave 0.52+ no longer bundles wandb — install it explicitly.)
# openai = the client used to call the LLM judge later.
pip install weave wandb openai

Re-run the source …/activate line in each new terminal; deactivate to exit. Prefer uv? uv venv ~/.venvs/weave-evals && source ~/.venvs/weave-evals/bin/activate && uv pip install weave wandb openai.

Inside this repo, skip uv run. The repo has its own pyproject.toml, so uv run ignores your activated venv and uses a separate .venv without weave. With (weave-evals) active, just call python … directly.
2

Authenticate

Either log in once interactively, or set the env var (better for scripts/CI):

# option A — interactive, stores the key in ~/.netrc
# (module form — works even if the wandb CLI isn't on your PATH)
python -m wandb login

# option B — env var (what the eval scripts expect)
export WANDB_API_KEY="<your-key>"
One key, two uses. This same WANDB_API_KEY later authenticates the LLM judge calls (Part 5) through W&B Inference — so you won't need a separate Anthropic or OpenAI key for scoring.
3

Create the project

The project is created the first time you log to it. Pick a name now — mirroring the author-docs convention (author-docs-evals), we'll use:

import weave

# Creates (or connects to) the project under your default entity.
client = weave.init("cw-add-users-evals")

print(client.entity, "/", client.project)

If you belong to a team and want it there explicitly, use weave.init("entity/cw-add-users-evals").

4

Prove it works — a "hello trace"

Before any eval machinery, confirm auth + project + tracing are wired. Run this whole snippet:

import weave

weave.init("cw-add-users-evals")

@weave.op()
def summarize_request(groups: list, users: list) -> dict:
    """Stand-in for real work — just so we see a trace."""
    return {"group_count": len(groups), "user_count": len(users)}

summarize_request(["engineering"], ["a@x.com", "b@x.com"])
Success looks like: the console prints a line like 🍩 https://wandb.ai/<entity>/cw-add-users-evals/r/call/.... Click it. You'll land in the Traces tab of your new project and see the summarize_request call, its inputs, and the returned dict. If you see that, your setup is correct and we're ready for Part 2.

Where this is heading (so today makes sense)

You told me the add-users eval has to answer two questions. Hold these in mind — they become the scorers in Parts 4-5:

QuestionHow we'll score itPart
Outcome: did every requested group & user actually end up in CoreWeave, with the right final status?A deterministic scorer comparing the requested set against the final observed state in the captured run.4
Advice quality: did the role recommendations follow our best practices?An LLM judge with a rubric built from references/roles.md and the skill's guidance.5
Why we're not running the skill for real. add-users sends real invitations and changes real org permissions. So the eval will score captured runs (a transcript + the final state), not live executions — that's Part 2. Same approach author-docs uses: score the artifact, don't regenerate it.
